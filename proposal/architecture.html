Data Model (JSON / Pydantic)

InventoryItem

  • id — string
  • sku — string
  • name — string
  • category — Circuit Boards | Sensors | Actuators | Controllers | Power Supplies
  • warehouse — San Francisco | London | Tokyo
  • quantity_on_hand — int
  • reorder_point — int
  • unit_cost — float
  • location — string
  • last_updated — ISO datetime

Order

  • id — string
  • order_number — string
  • customer — string
  • items — list of dicts
  • status — Processing | Shipped | Delivered | Backordered
  • order_date — YYYY-MM-DD
  • expected_delivery — YYYY-MM-DD
  • total_value — float
  • warehouse — optional string
  • category — optional string

DemandForecast

  • id — string
  • item_sku — string (FK to InventoryItem.sku)
  • item_name — string
  • current_demand — int
  • forecasted_demand — int
  • trend — increasing | stable | decreasing
  • period — string (e.g. Q4-2025)

Known Gaps & Risks

No persistent data store All data lives in Python memory; changes (purchase orders, tasks) are lost on server restart. Migration to PostgreSQL required for production.
No authentication API has no auth layer — all endpoints are open. CORS wildcard (*) accepted. Unsuitable for network-accessible deployment.
Incomplete Options-to-Composition API migration Reports.vue was the last view still using Options API; now remediated. Remaining components use Composition API consistently.
Single backend process, no load balancing Uvicorn runs as a single process. Any crash takes the API offline. Consider gunicorn with multiple workers or a process manager for production.
No error boundary on frontend A network failure mid-session shows an in-component error state but does not prevent navigation. Global error handling would improve resilience.

Current Deployment Topology

The system is currently developer-local only. Both processes must be started manually.
